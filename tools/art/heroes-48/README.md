# 主角 48×48 实战试用

2026-10-28 接入六位主角，共 840 帧。保留原生 32px 绘制源、原配色、造型和全部动画时序。新图集通过原绘制指令在 48px 网格上重绘曲线、斜线和单像素描边，不是平滑放大图片。

```sh
node tools/art/build_hero_sheets.mjs
npm run build
npm test
```

输出：`public/assets/heroes/*-48.png`（合计约 172 KiB）和 `src/art/heroAnimations.json`。修改原生角色后应重新生成；动画测试会检查导出的时序与原绘制源一致。缺失新图集时，该角色退回程序生成的原版。

默认启用 48px。`?heroPixels=32` 同时恢复原版主角和 1 倍渲染画布；已有参数时使用 `&heroPixels=32`。切换只作用于当前页面，不改变存档。去掉此参数恢复 48px。

主角局内占用仍为 32×32 世界单位，选角页仍为 64×64；碰撞半径、移速和攻击时间不变。桌面世界视野为 640×360，新渲染画布为 1920×1080，相机倍率为 3，CSS 保持原显示大小。手机横屏按屏幕比例扩展可见世界和画布，菜单与 HUD 留在安全区内；32px 回退模式也支持铺满。48px 模式下，旧素材每格占 3 个输出像素，新主角每格占 2 个，进入画布前不丢失新增细节。

同步适配了固定地面、光影层、风雪粒子、震屏强度、HUD 摇杆及洞府星图指针。Phaser 的震屏位移本身同时乘相机宽度和 zoom，因此通过原生 shake-start 事件抵消两次额外倍率。

验证：构建和 165 项测试通过；实测菜单点击、星图拖动、角色移动、摇杆、暂停、后续关卡风雪。六个原生角色源文件与试用前 SHA-256 一致，可恢复之前已接受的衣装和鼻梁版本。

本机浏览器压力测试：第 1 关，同屏 90 敌人，六种 8 级技能，光影开启；预热 2 秒、采样约 8 秒，32 / 48 均约 120 FPS，无超过 20ms 的采样帧。属于桌面短测，不能代表手机和完整后期战斗；渲染像素数增加 9 倍，慢设备可使用 32 入口。测试使用内存存档，没有修改日常游戏进度。
