## 当前搭配是否合适

以下百分比是配置中的抽取权重归一化，不是同屏占比或实际击杀占比；速度、生命、远程停留都会改变实战数量。

| 关卡 | 当前普通怪权重 | 判断与建议 |
|---|---|---|
| 1 荒郊古道 | 石俑 20%、藤怪 30%、水鬼 30%、火鸦 10%、铁甲兵 10%；狼妖 | 五系入门合理，但五种从开场同时进入随机池，水鬼 + 火鸦合计 40% 都偏快。保留阵容，先慢怪后快怪，最后才加入自爆。用荒坟、沟渠、残兵、野兽统一“荒郊”叙事。 |
| 2 竹林 | 藤怪 40%、竹叶青 30%、石俑 20%、瘴蟾 10%；千年树妖 | 最完整的一关：再生围堵、蛇冲锋、蟾吐毒，树妖继续召藤怪。保留。石俑可做苔封的古碑守卫，仍以土黄石身为主，避免全绿后被误认成木。 |
| 3 山林 | 石俑 30%、山魈 20%、穿山甲 20%、瘴蟾 10%、藤怪 20%；山魈王 | 山魈投石、穿山甲钻地、落石与 Boss 跳砸互相呼应。瘴蟾与山魈都属于 `spit`，区别主要是弹丸与异常，可让瘴蟾后段少量出现，先突出投石和钻地。 |
| 4 赤焰谷 | 火鸦 30%、赤狐 20%、火精 20%、石俑 30%；毕方 | 火鸦爆炸、赤狐留火、火精远射、毕方俯冲的主题很强。瘴蟾的湿毒意象最突兀，已按最低成本方案改掉：删掉此关瘴蟾，石俑权重 2→3，仍是火 70% / 土 30%，石俑用熔壳外观。缺少毒弹后的压力仍需实战确认。 |
| 5 兵冢古战场 | 残兵 40%、铁甲兵 20%、飞镰 15%、石俑 15%、穿山甲 10%；刑天 | 残兵复活 → 刑天复起，是最清楚的机制递进。保留前三者为主角。穿山甲的钻地能打破绕圈，但造型需带战场出土、破甲和骨片意象；土属性保持土褐主体，不画成全银金属兽。 |

石俑五关连用本身不是错误：可以作为玩家熟悉的慢速锚点。但五关完全一样会显得重复。优先共用骨架与行为，只做“古道陶俑 → 苔封俑 → 山岩俑 → 熔壳俑 → 残甲俑”的少量外形变化；元素主色和方形重装轮廓保持稳定。每关真正新增 1–2 个轮廓就足够。这一步已按此实现（见文首更新）。

第一关当前敌人比例是 **土 20 / 木 30 / 水 30 / 火 10 / 金 10**，与 GDD“各 20%”不同；五行均分的是地气。没有必要仅为凑平均而改权重，应先明确想教什么。

## 第一关出现节奏建议（尚未改配置）

| 时间 | 建议开启的普通怪池 | 学习点 |
|---|---|---|
| 0–30 秒 | 石俑、藤怪 | 移动、自动攻击、拾取；先认识慢重与再生 |
| 30–90 秒 | 加水鬼 | 学会处理快速追身；与 60 秒的第一只精英错开 |
| 90–150 秒 | 加铁甲兵 | 看懂直线预警、横向躲冲锋 |
| 150–300 秒 | 加火鸦，恢复完整五系 | 击杀后别贴着爆点；混合处理 |
| 300 秒起 | 狼妖 + 已学会的小怪 | 铁甲兵先教冲锋，狼妖再升级为冲锋后环射 |

这是待实测的时间安排，不是已经验证的平衡结论。实现时不能只改普通刷怪：`pickEnemy()` 同时供普通刷怪、成群事件、游荡精英和精英潮使用，所有入口都应遵守当时的解锁池。Boss 继续使用自己的固定配置。

## 第一关造型方向

| 怪物 | 从行为反推轮廓 | 本轮结果与下一步 |
|---|---|---|
| 石俑 | 方肩、短腿、厚拳、陶色大脸；不用长兵器 | 24px 可辨认。继续压缩胸甲碎纹，保持与我方细腰傀儡的差别。 |
| 藤怪 | 不对称根团、三根粗足、钩形藤臂、白木裂面 | 从圆绿团改为根爪妖。24px 面具偏小，28–32px 更合适；减少叶片数量，保住双臂间的空隙。 |
| 水鬼 | 前倾的脸、后拖的发、S 形水尾；浅脸深发 | 剪影能表达快速追击。已去掉缩图后的孤立发丝；后续原画宜把头发画成 2–3 大束，脸再放大，浅袖面积增加。 |
| 火鸦 | 尖喙、三角双翼、亮色胸部火囊 | 24px 可用。自爆提示不能只靠亮胸：需要额外死亡预警/爆炸帧，翅膀至少开合两态。 |
| 铁甲兵 | 比石俑更窄，斜向枪尖、空脸、冷白肩甲 | 长枪自然提示冲锋。28px 已能分辨，32px 更清楚。头盔仍有西式面甲感，下一版优先改成中式盔檐/护颈，减少红缨抢色。 |
| 狼妖 | 四足低伏、前肩厚重、刃状鬃毛、夸张前爪 | 56×48px 能保住面部和鬃毛，比现版更像 Boss。金属性用冷白铁鬃表达；半血变化可突出鬃毛与风刃，不改成另一个物种。 |

统一规则：朝右的浅俯视；左上光；暖深色 1px 外轮廓；每种有一个放大特征。主色服务元素辨识，轮廓服务行为辨识。精英优先增加角冠/护甲或底环，避免只改颜色；现有精英实际是原怪放大 1.5 倍、生命 ×10，尚未实现 GDD 的双元素精英。

## 实际完成的图像流程

1. 使用内置 `image_gen` 生成一张 1536×1024 的 3×2 整页，再做一次间距、细节与透明背景整理。提示词在 `../prompts/enemies-level1-v1.json`。
2. 保留原始图 `level1-v1/source.png`（2.1MB 生图原稿，和 `tools/art/raw` 一样不进仓库，只留在本地）。其 RGB 通道留有背景颜色，但空白区域 alpha 为 0；不得丢弃 alpha 后直接缩图。
3. 按 alpha 连通轮廓提取六只主体，不把生成的网格当成可靠切图坐标。边界记录在 `sprites.json`。
4. 每只先缩成 96×96 的低分辨率母图，组合为 `source-lowres.png`（384×256）。使用预乘 alpha 的 BOX 缩小，保持比例。
5. 再缩至 24 / 28 / 32px；原尺寸版中铁甲兵 28×28，狼妖 56×48。统一 38 色色板，无抖动；提升中间色，去除 1–2 像素的孤岛，硬 alpha、补 1px 描边。
6. PNG 使用索引色。六张当前尺寸切片合计 **6712 字节**；原图和对照页放在开发素材目录，没有进入 `public`，不增加正式首屏负担。

代码只负责已有图像的切片、缩放、调色、透明处理和对照排版，没有用坐标代码画怪物。（2026-10-18 更新：正式敌人贴图改为程序画重制；试稿管线本身仍只做切片/缩放/调色。）

重跑：

```sh
python3 tools/art/pixelize_enemies.py
node tools/art/check_enemy_study.mjs
```

预览（运行已有 Vite 服务）：`http://localhost:5180/tools/art/enemies/index.html`。支持现有/新造型、当前尺寸/32px、1×/2×、24/72/160 只排列、灰度、模糊和剪影。

## 验证结果与边界

初次直接缩图的多数主体在古道地面上偏暗。保留优化前指标 `validation-before.json`；提亮与轮廓整理后，六只当前尺寸切片的明度差均达到 0.12 门槛：

| 石俑 | 藤怪 | 水鬼 | 火鸦 | 铁甲兵 | 狼妖 |
|---|---|---|---|---|---|
| 0.229 | 0.244 | 0.241 | 0.207 | 0.249 | 0.380 |

指标沿用项目的 OKLab 转换，对比主体（排除新增描边）的平均/75 分位明度与第一关地面 95 分位明度；也校验 alpha 仅有 0/255、单张颜色不超过 38。数字只能证明静态对比度，不等于小尺寸身份、动画或密集战斗可读性都已过关。

已运行：项目 TypeScript 检查通过；独立预览脚本 TypeScript 检查通过；原有 25 项测试通过（其中原有可读性测试覆盖正式旧素材）；另跑新素材静态检查 6/6 通过。浏览器检查了对照页及原尺寸、高密度、灰度切换。

本轮没有替换正式贴图：当前仅一帧造型，不能复制同一张图假装移动动画。（2026-10-18 更新：正式敌人贴图已改为程序画新造型并带 2 帧移动；本句现在只适用于 `level1-v1/` 的试稿 PNG，它们仍未接入战斗。）下一步应先把一只普通怪做成 2–4 帧移动 + 蓄力/攻击的真实动作，再以现有 `tex` / `_move` key 接入。保留加载失败回退；对照 640×360 战斗画面检查宝石、预警、受击闪白、精英缩放和遮挡。接入仍用原碰撞半径，视觉变大不自动增大碰撞；明确脚底锚点，元素环单独处理。Boss 最后做前摇和攻击动作。
